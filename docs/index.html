Using dbstim

dbstim is a Python 3.11+ client for creating experiments on dbstimuli.com, downloading SHA-256-verified stimulus videos, and recording trial progress from your task program.

Your task plays the video PGL, PsychoPy, or your own player opens the window, controls frame timing, and collects responses.
The server tracks progress Publishing freezes each subject's trials. The server records which trials started, completed, or were abandoned.
One local cache per user session.download() verifies MP4s into ~/.cache/dbstim, where task scripts in any folder can reuse them.
Reference map See the interactive API map, download api-interface.md, or read API Objects and Server-to-Local Flow for class diagrams and request sequences.

1. Install

dbstim requires Python 3.11+ and uses only the standard library at runtime. Install it from a pinned GitHub tag (currently v0.5.0) or commit SHA so your study environment stays reproducible; it is not published on PyPI. 

# Install with pip
pip install "git+https://github.com/lobennett/dbstim.git@v0.5.0"

# Or add to a uv project
uv add "dbstim @ git+https://github.com/lobennett/dbstim.git@v0.5.0"

# Optional: include JupyterLab (>=4,<5) for notebooks/api.ipynb
pip install "dbstim[jupyter] @ git+https://github.com/lobennett/dbstim.git@v0.5.0"

Sign in with your dbstimuli.com account—no Google Cloud SDK or separate API key is needed. dbstim replaces the legacy dbp_api package (d11933f).

2. Connect

In interactive terminals or notebooks, dbstim.connect() prompts for your username and reads your password via getpass: 

import dbstim

client = dbstim.connect()
client = dbstim.connect("your_username")  # prompts only for password

In scripts, pass credentials or environment variables to Client directly: 

from dbstim import Client

with Client(
    "your_username",
    "your_password",
    url="https://dbstimuli.com",  # HTTP is allowed only for localhost
    timeout=120,
) as client:
    print(client)  # <Client your_username at https://dbstimuli.com>

Session cookies and the CSRF token stay in memory and are cleared by client.close(), leaving with client:, or an HTTP 401. Remote URLs must use https:// without embedded credentials, paths, or query strings, and the client never follows redirects.

3. Filter by metric

client.metrics() lists the catalog metrics you can filter on when creating an experiment. Each Metric(id, label, kind, unit, operators) shows its allowed comparison operators: 

from dbstim import MetricFilter

metrics = client.metrics()
for metric in metrics:
    print(repr(metric))
# <Metric duration_seconds: Duration (number, seconds); operators > >=>

filters = [
    MetricFilter("duration_seconds", ">=", 10),
    MetricFilter("duration_seconds", "<=", 20),
    MetricFilter("audio_track_present", "==", True),
]
  • Operators: Numeric metrics accept ">=", "<=", ">", "<", and "==" (or "gte", "lte", "gt", "lt", "eq"). Boolean metrics accept "==" and "!=" with True or False ("!=" is only for booleans).
  • Matching: Filters combine with AND, and clips with unknown (NULL) values do not match. Pass content="..." and corpus="captions" | "transcripts" | "both" to create_experiment(...) to filter by clip text as well. See Metrics & Filters for how the server indexes and queries metrics.

4. Create, publish, and reopen experiments

Create and publish

client.create_experiment(...) checks your design counts and saves a draft on the server. Call experiment.publish() to freeze each subject's sessions, runs, and trials before reading experiment.subjects: 

experiment = client.create_experiment(
    "Memory demo",
    subjects=5,
    sessions_per_subject=1,
    runs_per_session=2,
    trials_per_run=24,
    foils_per_run=4,
    repeats_per_run=0,
    shared_fraction=0.1,
    seed=1,
    sampling="random",  # "random", "balanced", or "unique" YouTube channels
    filters=[
        MetricFilter("duration_seconds", ">=", 10),
        MetricFilter("duration_seconds", "<=", 20),
    ],
    content="",
    corpus="both",      # "captions", "transcripts", or "both"
)

experiment.publish()
summary = experiment.summary()
print(summary["id"], summary["published"], summary["shared_fraction_realized"])
  • Run composition: Foils (second halves of split parent clips) and repeats count toward trials_per_run. Each run presents parents = trials_per_run - foils_per_run - repeats_per_run parent clips (parents >= 1, max(foils_per_run, repeats_per_run) <= parents)—parents - foils_per_run full clips and foils_per_run first halves—plus foils_per_run second-half foils and repeats_per_run repeats.
  • Limits and shared clips: Up to 100 subjects and 50,000 total presentations. shared_fraction (0 to 1) sets the share of parent clips every subject sees, rounded down to whole videos (warning on rounding and reporting the exact value in summary["shared_fraction_realized"]).

Reopen an existing experiment

Every create_experiment(...) call creates a new experiment on the server, even if the name already exists. Reopen an existing one with client.experiment(name)—if multiple experiments share that name, the ValueError lists their revision IDs so you can pass id=: 

all_experiments = client.experiments()

experiment = client.experiment("Memory demo")
experiment = client.experiment(id="experiment-1")  # disambiguate duplicate names

5. Download media vs. present a session

dbstim separates downloading video files from running a tracked session. Downloading or previewing files never claims a session or changes participant progress.

A. Download videos ahead of time (untracked)

Run session.download() in a setup script or notebook before the participant arrives. It downloads and verifies every MP4 for the session into ~/.cache/dbstim: 

experiment = client.experiment("Memory demo")
session = experiment.subjects[0].sessions[0]

cache_folder = session.download()

run = session.next_run()
if run is not None:
    first_mp4 = run.media(run.trials[0], mode="local")
  • Shared cache: Files live under $XDG_CACHE_HOME/dbstim or ~/.cache/dbstim, so task scripts in any folder reuse what you already downloaded.
  • Custom folder: session.download("/path/to/dir") or subject.session("session-001", directory="/path/to/dir") uses that directory as given—give each session its own folder on a filesystem that supports hard links (not exFAT or FAT).

B. Run a tracked session

Wrap presentation in with session: and step through session.next_run() and run.next_trial(). Your present(path) function plays the video and returns a plain-JSON result dictionary (or None): 

session = experiment.subjects[0].sessions[0]

with session:  # claims the session and finishes it on exit
    while (run := session.next_run()) is not None:
        while (trial := run.next_trial()) is not None:
            path = run.media(trial)
            run.record(trial, "started")
            result = present(path)  # your PGL or PsychoPy function
            run.record(trial, "completed", result=result)
  • Session outcome: Leaving with session: finishes the session as "completed" when every trial is completed, "interrupted" if you stop early (including Ctrl-C) or abandon a trial, or "failed" if an exception escapes the block.
  • Your code verifies playback: dbstim only records what present(path) returns; it cannot see the screen. In PGL, play() returning does not prove frames were shown—check frame timestamps before recording "completed".
  • Trial fields: Each Trial has trial_id, stimulus_id, position (1-based), role ("parent", "repeat", or "foil"), media_type="video", and segment (Segment(start_seconds, end_seconds) or None). Split halves and foils are already trimmed to play from time zero.

Media modes (run.media(trial, mode=...))

  • mode="cache" (default): Returns the verified local Path if cached, or downloads it on the spot. Calling run.media(trial) without pre-downloading fetches missing video inside your trial loop.
  • mode="local": Uses only an already-downloaded file and raises ApiError immediately if it is missing. Call session.download() before with session: and pass mode="local" inside the loop so presentation never waits on a download.
  • mode="remote": Requests a 5-minute streaming URL from the server without saving to disk; your player streams over the network during playback.

6. Network vs. local calls

Every network call in dbstim is synchronous. Keep server requests between trials—or before the session—so they never block frame rendering. See Server-to-Local Flow for the full request sequence.

Operation I/O Type Behavior & Timing
connect(), Client(...), client.metrics(), client.experiments(), client.experiment(...), client.create_experiment(...), experiment.publish(), experiment.summary() HTTP Synchronous HTTPS requests. Run during setup or startup.
experiment.subjects HTTP (1st) Local (cached) First access fetches all subject manifests; later accesses on the same Experiment reuse memory (experiment.subject(id) always fetches over HTTP).
subject.sessions, subject.session(id), subject.session_ids, session.run_ids, session.run("run-001"), run.trials, trial.*, repr(...) Local (Memory) Reads manifest data already in memory; no disk or network I/O.
session.download() HTTP + Disk Downloads missing MP4s and verifies SHA-256 checksums for the session. Run before with session:.
run.media(trial, mode="local")
(or mode="cache" when cached)		 Local (Disk SHA-256) No network I/O, but hashes the full MP4 file with SHA-256 on every call to verify its receipt. Resolve the path before drawing your first frame.
run.media(trial, mode="remote") HTTP Requests a 5-minute streaming URL (POST); the player then streams over the network during playback.
session.next_run(), session.run("latest"), run.next_trial(), session.unconfirmed, session.abandoned, session.results, run.results HTTP GET (No retry) Fetches session state from the server on every call or property access. Reads are not retried: a dropped read raises ApiError, and leaving with session: on that error marks the session "failed".
session.start(), session.finish(), run.record(...), session.record(...) HTTP POST (Retried) Sends an idempotent write. On connection errors or HTTP 500/502/503/504, retries up to 3 times (0.5s, 1.0s, 2.0s pauses) with the same request ID so events are never duplicated.

7. Results and recovery

See Recovering a Session for the complete recovery reference.

Result payloads

run.record(trial, status, result=...) checks result before sending: it must be None or a plain JSON dict (str, int, finite float, bool, None, list, dict). Convert NumPy scalars with int(x) or float(x), and pass None when there is no response: 

run.record(trial, "completed", result={"rt_ms": int(412), "choice": "left", "confidence": None})

all_results = session.results
current_run_results = run.results

session.results and run.results list only trials recorded with a non-None result dict; session.abandoned lists every abandoned trial even when result=None.

Interrupted (unconfirmed) trials

Every started trial ends once as "completed" (shown to the end) or "abandoned" (cut short); neither is ever replayed. If a process stops after record(trial, "started"), that trial stays in session.unconfirmed and blocks run.next_trial() across the session until you resolve it: 

session = experiment.subjects[0].sessions[0]

with session:
    # Record "completed" only if the participant saw the full video
    for trial in session.unconfirmed:
        session.record(trial, "abandoned", result={"reason": "stopped mid-trial"})

    while (run := session.next_run()) is not None:
        while (trial := run.next_trial()) is not None:
            path = run.media(trial)
            run.record(trial, "started")
            result = present(path)
            run.record(trial, "completed", result=result)

print(session.abandoned, session.results)
Abandoned trials mark the session "interrupted" Even after all remaining trials complete, a session with an abandoned trial finishes as "interrupted"; calling session.finish("completed") fails with HTTP 409.

Failed writes and session takeover

If a write (start(), finish(), or record()) still fails after its 3 automatic retries, dbstim keeps that command pending on the Session object and blocks next_run(), next_trial(), and finish() until you repeat the same call on that instance (4xx errors are not retried).

If the script exited before leaving with session:, a new session.start() raises ApiError (HTTP 409: Another presenter owns this session). After confirming the old process has stopped, claim the session with takeover=True: 

# Only after confirming the previous process has stopped:
session.start(takeover=True)
with session:
    for trial in session.unconfirmed:
        session.record(trial, "abandoned", result={"reason": "previous process crashed"})
    while (run := session.next_run()) is not None:
        while (trial := run.next_trial()) is not None:
            path = run.media(trial)
            run.record(trial, "started")
            result = present(path)
            run.record(trial, "completed", result=result)

8. Limitations and upgrading

  • Live server required for progress: Videos cache on disk, but creating experiments, claiming sessions, reading progress, and recording trials require HTTPS access to the server. Offline event queuing and standalone export bundles are not supported.
  • Server support for "abandoned": Recording "abandoned" requires dbp-dataset-browser 492a894 or later with its database migration applied. On older servers, record(trial, "abandoned") raises ApiError (HTTP 400) and leaves the trial unconfirmed.
  • Upgrading from 0.4 to 0.5: Version 0.4 cached videos in ./.dbstim and could not advance past an abandoned trial. Version 0.5 uses ~/.cache/dbstim and ignores old .dbstim folders, which you can delete.
  • Verification scope: All examples and behaviors in this guide were verified against dbstim v0.5.0 and local HTTP test fixtures, without creating experiments or modifying state on the live dbstimuli.com server. Production behavior depends on the server revision and database migrations currently deployed.
