Using dbstim

dbstim is a Python 3.11+ client for dbstimuli.com. Choose videos by metric, download them as a portable BIDS stimuli folder, and record which videos your task showed. Recording happens offline; you sync afterwards.

A. Download for your own code create() then download(): verified MP4s with a manifest.json and a PGL-loadable manifest.csv. No subjects or tracking.
B. Track a run Check a subject session out online, record the run offline in a crash-safe journal, then sync(). Nothing touches the network during the run.
Your task plays the video PGL, PsychoPy, or your own player opens the window, controls frame timing, and collects responses.
Reference map See the interactive API map, download api-interface.md, or read API Objects and Experiment to Events File. The repository's notebooks/api.ipynb walks through both journeys.

1. Install

dbstim requires Python 3.11+ and uses only the standard library at runtime. Install it from a pinned GitHub tag (currently v1.0.0) or commit SHA so your study environment stays reproducible; it is not published on PyPI. 

# Install with pip
pip install "git+https://github.com/StanfordDigitalBrainProject/dbstim.git@v1.0.0"

# Or add to a uv project
uv add "dbstim @ git+https://github.com/StanfordDigitalBrainProject/dbstim.git@v1.0.0"

# Optional: include JupyterLab (>=4,<5) for notebooks/api.ipynb
pip install "dbstim[jupyter] @ git+https://github.com/StanfordDigitalBrainProject/dbstim.git@v1.0.0"

Sign in with your dbstimuli.com account; no Google Cloud SDK or API key is needed. Version 1.0 changes the API; the changelog lists what moved.

2. Connect

In terminals and notebooks, dbstim.connect() prompts for your username and reads your password via getpass: 

import dbstim

client = dbstim.connect()
client = dbstim.connect("your_username")  # prompts only for the password

In scripts, pass credentials to Client directly:

from dbstim import Client

with Client(
    "your_username",
    "your_password",
    url="https://dbstimuli.com",  # HTTP is allowed only for localhost
    timeout=120,
) as client:
    print(client)  # <Client your_username at https://dbstimuli.com>

Session cookies and the CSRF token stay in memory and are cleared by client.close(), leaving with client:, or an HTTP 401. Remote URLs must use https:// without embedded credentials, paths, or query strings. The client follows no redirects, except that a video download may hand off to a signed Google Cloud Storage URL, fetched without your account cookies.

3. Choose videos

client.metrics() lists the metric names you can filter on. A Filter compares one metric with a threshold; a video must match every filter. 

from dbstim import Filter

client.metrics()  # ['duration_seconds', 'width_px', ...]

experiment = client.create(
    "Clips",
    filters=[Filter("duration_seconds", ">=", 10), Filter("audio_track_present", "==", True)],
    count=40,  # how many videos, 1-50,000
    seed=1,    # same filters, count and seed: same selection
)
experiment.name, experiment.revision, experiment.videos

An experiment is a frozen selection: later catalog changes never alter it. Names are unique in your account; create() with a name you already use raises ApiError (HTTP 409) and suggests open(). Use >, >=, <, <= or == with numbers, and == or != with True/False. 

experiment = client.open("Clips")              # latest revision
experiment = client.open("Clips", revision=1)  # an earlier one
experiment = client.open(id="...")             # exact revision, e.g. from manifest.json

newer = experiment.replace(["video-id-to-drop"], reason="blurry")  # new revision

schedule() and replace() return a new revision and leave the one you called unchanged.

4. Journey A: download videos for your own code

download(folder) writes a portable BIDS 1.11.2 folder that works without dbstim. Each video is checked against its size and SHA-256 before it takes its final name; running it again reuses verified files. A folder that holds another revision is refused. 

folder = experiment.download("clips_bids")
PathContents
dataset_description.json, READMEBIDS dataset name and generator; what the folder holds
stimuli/*.mp4the videos; foil halves are separate files
stimuli/manifest.jsonexperiment id, revision, filters, seed, and every file's size, SHA-256 and duration
stimuli/manifest.csvfilename, index, id, sha256, bytes, duration: one row per movie, the single CSV PGL's movie database expects

No subjects, scheduling or tracking are involved.

5. Journey B: a tracked run

Online once before, offline for the whole run, online once after. The run is the protected window: nothing in it contacts the website, so the network can never stall the display.

Online, before: schedule and check out

schedule() adds subjects, sessions and runs as a new revision. checkout() reserves one subject session for this computer and downloads only its videos and run plans. 

scheduled = client.open("Clips").schedule(
    subjects=5, sessions=1, runs=2, trials_per_run=8,
    foils_per_run=0, repeats_per_run=0, shared_fraction=0,
)
scheduled.checkout(subject=1, session=1, folder="sub01_ses01")

Another computer's checkout fails with HTTP 409 until it passes takeover=True. Use a new folder for each subject session.

Offline: record the run

dbstim.session(folder) reopens the checkout without the network. Iterating a run yields the trials with no outcome yet, in order. Every call is written to disk before it returns. 

session = dbstim.session("sub01_ses01")
with session.run(1) as run:
    for trial in run:  # Trial(number, file, video_id, role)
        run.started(trial, onset=now() - t0)
        shown = play(trial.file)  # your presentation code
        if shown.full:
            run.completed(trial, duration=shown.seconds,
                          result={"key": shown.key})
        else:
            run.abandoned(trial, duration=shown.seconds)

Online, afterwards: sync

session.sync()  # {1: 'accepted', 2: 'waiting'}

onset is seconds from the time zero your code chose, such as the scanner trigger. completed and abandoned are your code's claims; dbstim records them and never checks the display. trial.role is "video", "repeat" or "foil"; foil halves are already cut, so play them from time zero.

With PGL PGL owns the loop, so the calls go in your pglTask hooks around e.run(): start the trial when its movie segment starts, then record completed or abandoned after movie.play() returns, and abandon an open trial when Escape ends the task. The documented example is examples/pgl_tracked_movie_task.py; it is user code, and dbstim does not import PGL.

6. Events and frame timing

Leaving the with block writes sub-01/ses-01/beh/sub-01_ses-01_task-dbstim_run-01_events.tsv and a JSON sidecar describing each column. The journal in stimuli/.dbstim/ is the record; the events file is rebuilt from it.

ColumnValue
onsetseconds from your run's time zero, as reported
durationseconds shown, as reported; n/a if unknown
trial_typevideo, repeat or foil
stim_filemovie name in stimuli/
video_idcatalog video id
planned_durationthe movie's length from the manifest
outcomecompleted or abandoned
partrecording part, from 1; resuming a run starts a new part
resultyour result as compact JSON, or n/a

dbstim.frame_summary(presented_times, movie_times, duration) turns PGL's per-frame arrays into evidence for the result. Zero or non-finite presentation times count as dropped frames: 

summary = dbstim.frame_summary(movie.presentedTimes, movie.movieTimes, movie.duration)
# {'frames_shown': 135, 'frames_dropped': 0, 'seconds_shown': 4.5, 'reached_end': True}
run.completed(trial, duration=summary["seconds_shown"], result=summary)

A result is None or a plain JSON dict. Timing arguments accept NumPy numbers; inside a result, convert them with int() or float(). Behavioral responses and PGL's own data files stay with your task.

7. Network vs. local calls

Every network call is synchronous. Journey B keeps them all outside the run.

OperationI/O TypeBehavior & Timing
connect(), client.metrics(), client.create(...), client.open(...), experiment.schedule(...), experiment.replace(...) HTTP Synchronous HTTPS requests during setup.
experiment.download(folder), experiment.checkout(...) HTTP + Disk Download missing MP4s and verify each one. While the server prepares a video it answers 503 with Retry-After; dbstim waits, for up to five minutes.
dbstim.session(folder), session.run(n), for trial in run Local Read the checkout's files; no network.
with run:, run.started, run.completed, run.abandoned Local (Disk fsync) Append one journal line and force it to disk before returning. Leaving the block rewrites the events file.
session.sync() HTTP For each closed run without a receipt: check for a stored copy, then upload it. Run it after the session.

8. Recovery and sync

See Recovering a Run for the complete reference.

A crash, power cut or Ctrl-C

Open the same run again on the same computer and keep looping. A trial started with no ending is recorded abandoned (duration n/a) and never shown again; the loop continues with the next trial, in a new part. A half-written last journal line is dropped. 

session = dbstim.session("sub01_ses01")
with session.run(1) as run:
    for trial in run:  # continues after the last trial with an outcome
        ...

Only one program may have a session open: a second recorder, or a sync during a run, raises RuntimeError. The lock is released when the program exits, even by crashing.

Ending a run early

A run syncs only once every trial has an outcome. Until then sync() reports it as "waiting" and you can continue it later. To close a run you will not finish, start and abandon each remaining trial.

Moving to another computer

# On the new computer, only after the old one has stopped presenting:
experiment.checkout(subject=1, session=1, folder="sub01_ses01", takeover=True)

An unfinished run belongs to the computer that started it and cannot move. Runs the first computer syncs after a takeover are "kept as flagged attempt": the server stores them separately, and their events move to sourcedata/attempt-<id>/.

Sync outcomes

OutcomeMeaning
"accepted"stored on the server by this call
"already synced"stored earlier, including when the reply was lost
"kept as flagged attempt"stored as a flagged attempt after a takeover
"waiting"not closed yet; nothing sent
 
try:
    outcomes = session.sync(client=client)  # or let it prompt for the password
except dbstim.SyncError as error:
    print(error.refused)   # {1: ApiError(...)}: refused runs
    print(error.outcomes)  # every other run's outcome
A refused run does not block the others sync() tries every closed run, then raises SyncError if the server refused any, for example a run another computer already synced. After a dropped connection (ApiError), run sync() again: the same record is resent and stored once.

9. Upgrading and limits

  • Upgrading from 0.5: 1.0 removes Subject, the online session API (with session:, next_run(), next_trial(), record(), media()) and the ~/.cache/dbstim cache. 1.0 cannot continue a 0.5 session; finish it with v0.5.0, which stays installable.
  • Server version: 1.0 needs a server with selections, experiment media manifests and run sync (dbp-dataset-browser 6799d6d or later).
  • Not part of dbstim: rendering, judging whether a video was seen, uploading videos, and a PGL adapter.
  • Verification scope: The notebook and the test suite were run with dbstim v1.0.0 against the real server code on temporary local databases, without changing anything on the live dbstimuli.com server. The PGL example has not yet been run with PGL; it is validated in a hands-on session after 1.0.
