1Mental model

An Experiment is a frozen selection of videos. You can stop at a downloaded folder (journey A), or schedule subjects and check one subject session out to the presentation computer (journey B). A tracked run then happens entirely offline, and you sync it afterwards.

dbstimuli.com owns

  • the video catalog and filterable metrics
  • saved experiments and their revisions
  • which computer holds each subject session
  • synced runs and flagged attempts

dbstim does

  • validates arguments before sending them
  • verifies every video by size and SHA-256
  • keeps the crash-safe journal and writes BIDS events
  • syncs each closed run once

Your program owns

  • rendering: PGL, PsychoPy or any player
  • timing, responses and what goes in a result
  • saying whether a trial was shown to the end

2Journey A: download videos for your own code

Three calls from nothing to a portable folder. No subjects, scheduling or tracking are involved.

import dbstim
from dbstim import Filter

client = dbstim.connect()   # asks for your password
experiment = client.create(
    "Clips", filters=[Filter("duration_seconds", ">=", 10)],
    count=40, seed=1,
)
folder = experiment.download("clips_bids")
# later, any computer: client.open("Clips")
  1. connect() asks for credentials, then signs in HTTP. The cookie lives only in memory; client.close() forgets it.
  2. create() checks every argument local, then samples count matching videos with the seed and saves revision 1 HTTP. Reopen it with client.open("Clips"), or an earlier revision with revision=.
  3. download() fetches each video not yet verified HTTP disk and returns the folder's Path. A second call downloads nothing.

3Journey B: a tracked run

Online once before, offline for the whole run, online once after. The run is the protected window: nothing in it contacts the website, so a slow network can never stall the display.

# online, before
scheduled = client.open("Clips").schedule(
    subjects=5, runs=2, trials_per_run=8)
scheduled.checkout(subject=1, session=1, folder="sub01_ses01")

# offline, on the presentation computer
session = dbstim.session("sub01_ses01")
with session.run(1) as run:
    for trial in run:
        run.started(trial, onset=now() - t0)
        shown = play(trial.file)        # yours
        if shown.full:
            run.completed(trial, duration=shown.seconds,
                          result=shown.summary)
        else:
            run.abandoned(trial, duration=shown.seconds)

# online, afterwards
session.sync()   # {1: "accepted", 2: "waiting"}
  1. schedule() saves a new revision with subjects, sessions and runs HTTP.
  2. checkout() reserves the subject session for this computer and downloads only its videos and run plans HTTP disk.
  3. dbstim.session(folder) reopens it anywhere on this computer local.
  4. Inside with session.run(1), each call appends to the journal and forces it to disk disk. Your code plays the movie yours.
  5. sync() uploads each closed run once HTTP.
With PGL, PGL owns the loop: call run.started, run.completed and run.abandoned from your pglTask hooks around e.run(), and pass dbstim.frame_summary(movie.presentedTimes, movie.movieTimes, movie.duration) as the result. See examples/pgl_tracked_movie_task.py.

4Trial outcomes and sync

completed is your code's claim; dbstim never checks the display. A run closes once every trial has an outcome. session.sync() returns one outcome per run:

OutcomeMeaning
"accepted"Stored on the server by this call.
"already synced"Stored earlier, including when the reply to an earlier sync was lost.
"kept as flagged attempt"Another computer took the session over; the server keeps this run separately and its events move to sourcedata/.
"waiting"Not closed yet; nothing sent.

A run the server refuses does not stop the others. After trying them all, sync() raises SyncError, whose refused maps each run number to its error and outcomes holds the rest.

5Recovery

Crash or power cut

Open the same run again on the same computer. A trial started with no ending becomes abandoned (duration n/a); the loop continues with the next trial and a new part. A half-written final line is dropped.

Ending a run early

Escape or quitting leaves unrecorded trials open: sync() says "waiting" and the run can be continued later. To close it without them, start and abandon each remaining trial.

Another computer

Its checkout fails with HTTP 409 until it passes takeover=True. Runs the first computer syncs afterwards are kept as flagged attempts. An unfinished run cannot move between computers.

Sync problems

After a dropped connection, run sync() again: the same record is resent and stored once. A changed record for a stored run is always refused. Only one recorder or sync may hold a session at a time (RuntimeError).

6The BIDS folder

download() and checkout() write the same BIDS 1.11.2 layout; a checkout adds the run state and, after runs, the events files.

8Boundaries

Not part of dbstim

  • Rendering, display timing or input handling.
  • Judging whether a trial was seen: your code says so.
  • A PGL adapter: the example is user code, and dbstim does not import PGL.
  • Uploading videos, or behavioral responses and PGL's own data files.

Good to know

  • Synchronous; a Client and its objects are not thread-safe.
  • Video is the only media type; foil halves are separate files.
  • A checkout folder holds one subject session; use a new folder for each.
  • Python 3.11+, no runtime dependencies.
